North star

OODA becomes the canonical personal deliberation layer inside Bob and the default daily LLM interface. Mobile and web share a durable conversation history, privacy-gated context, voice input, interruptible speech, bounded research and scratch workers, attention stewardship, and inspectable proposals that hand approved durable work to Bob.

Lifecycle: utterance → memory seed → enriched possibility → proposal → approved commitment → execution evidence → reflection. Most utterances stop before commitment.

Core invariants

Durability

  • Event history is append-only and event-sourced.
  • All writes carry device idempotency keys.
  • Every projection is rebuildable.
  • Corrections supersede; they do not erase.

Privacy

  • Raw microphone audio is discarded after transcription.
  • Exact disclosed context is inspectable.
  • Sensitive cloud and speech disclosure is denied without applicable permission.
  • Credentials never reach client code or event payloads.

Autonomy

  • Bounded research and scratch jobs may run automatically.
  • Workers receive explicit paths, capabilities, budgets, and no inherited credentials.
  • Scratch artifacts expire unless promoted.

Commitment

  • Private proposals may be drafted automatically.
  • Durable or external work requires immutable approval.
  • Deploy, publish, purchase, credential, and destructive actions require just-in-time approval.

Versioned contracts live in packages/ooda/src/contracts/v1. Typed tRPC plus HTTP/SSE expose conversations, events, context previews, memories, jobs, proposals, decisions, links, and receipts. Lists use cursors; all failures share ProblemV1.

Voice-first daily driver

  • Open to the last active conversation with a native searchable drawer, pins, branches, and “new thought.”
  • Keep hold, lock, and cancel STT gestures; make low-confidence transcripts editable before submission.
  • Persist an offline event outbox across app restarts with visible queued, syncing, and failed states.
  • Stop speech before barge-in recording begins. Store both full display and concise speakable responses.
  • Stream ElevenLabs audio through a short-lived authenticated server proxy; never ship its API key.
  • Suppress automatic speech for code, tables, credentials, and policy-blocked sensitive content.

Delivery contract

interface DomainAdapter {
  inspect(input: InspectInput): Promise<ContextReceipt>;
  validateProposal(proposal: ProposalV1): Promise<ValidationReceipt>;
  commit(proposal: ProposalV1, idempotencyKey: string): Promise<ExternalReceipt>;
  lookupByIdempotencyKey(key: string): Promise<ExternalReceipt | null>;
  readStatus(link: ExternalLinkV1): Promise<ExternalStatus>;
  cancel?(link: ExternalLinkV1): Promise<ExternalReceipt>;
}

Adapters land in order: Obsidian, Bob, KanBanger read/status, BizPulse, ForgeGraph, Creator, FabForge, Veritas, and Preflight. Every write is kill-switchable, validated against fixtures, and proven in a sandbox or staging environment before enablement.

Implementation milestones

  • Phase 0 — Safe foundation and source inventory
    Pin the deployed base, isolate work, rehearse restore, record migration dispositions, and preserve every user change.
  • Phase 1 — Contracts, event store, and migrations
    Ship V1 public types, canonical schemas, idempotent backfill, transcript hashes, rollback, and deterministic projections.
  • Phase 2 — Kernel API and stream
    Add transactionally sequenced append, cursor reads, correction/fork semantics, resumable SSE, and edge/Node contract parity.
  • Phase 3 — Mobile daily driver and TTS
    Unify chat, add offline reconciliation, typed virtual timeline, drawer, secure streaming TTS, and barge-in.
  • Phase 4 — Host routing, context policy, and workers
    Provider continuity/fallback, disclosed context packs, explicit capabilities, disposable sandboxes, and bounded jobs.
  • Phase 5 — Memory, imports, and attention
    Unify native and imported histories, pgvector search, deterministic callbacks, opportunity review, and review projections.
  • Phase 6 — Critical execution chain
    Proposal → approval → Bob → KanBanger → agent run → ForgeGraph evidence → reflection.
  • Phase 7 — Portfolio and specialist adapters
    Connect BizPulse and the Creator, fabrication, hardware, and mobile-release domains without copying their canonical facts.
  • Phase 8 — Web parity and legacy retirement
    Share contracts/view models, redirect legacy routes, end dual writes, and archive the standalone implementation after parity.
  • Phase 9 — Production dogfood and expansion
    Enable capabilities progressively and require a 14-day zero-loss dogfood period before Grok replacement is declared complete.

Attention stewardship

Memory follows captured → enriched → incubating → proposed → committed → completed → reflected, with dismissed, merged, and killed exits. Opportunity scoring balances expected value, strategic fit, evidence, timing, synergy, energy, reversible learning, and an opportunity-cost penalty.

Production success gates

  • Zero lost accepted turns, duplicate durable objects, or unauthorized sensitive disclosures during the 14-day dogfood window.
  • Every external write has a proposal, approval, idempotency key, receipt, and deep link.
  • Offline submissions reconcile automatically and the mobile app replaces Grok for routine daily conversations.
  • At least one real project completes the OODA → Bob → KanBanger → ForgeGraph → domain evidence loop.
  • The standalone OODA implementation retires only after verified data and behavior parity.

Decisions

No open product decisions. Personal-first tenancy seams, Bob as canonical monorepo, OODA as complete conversation store, curated-only Obsidian export, Grok-hosted turn-based voice, on-device STT, ElevenLabs-only TTS, offline capture, bounded autonomous research/scratch work, and approval-gated durable execution are approved defaults.
