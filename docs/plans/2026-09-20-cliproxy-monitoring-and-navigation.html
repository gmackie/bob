Overview

CLIProxyAPI is already running in production: six subscription accounts (two Claude, two Codex Pro, Kimi, xAI), five API keys, remote management enabled, usage statistics on. The primary runner host already routes gateway sessions through it by way of a host-managed environment file and a Codex model_provider entry. That is the whole integration today, and it has three gaps this plan closes:

  • The proxy is invisible to Bob. Nothing in the codebase references it except one ops doc. Nodes, Providers and Runs render host-local credential probes that no longer describe what is actually serving inference.
  • Monitoring is wrong in production right now. The host credential probe checks ~/.claude/.credentials.json and codex login status directly, reports Grok as "missing", and its unit is in a failed state — while the proxy holds a working xAI account. The proxy is the source of truth and nothing reads it.
  • Half the execution paths bypass the proxy. Isolated OODA agent jobs build their environment from a broker that forwards only PATH, LANG, LC_ALL and TERM; the proxy variables never reach them, so they still copy OAuth credential files per run.

The approach: make proxy a first-class provider auth mode in the runner, feed proxy state into the same host-snapshot heartbeat that already drives the agent lights, expose it through RPC to web and mobile, and then do a navigation and polish pass across both surfaces so every screen is reachable and reads as one product.

Goals & Non-goals

Goals

  • Every agent run — gateway sessions and isolated OODA jobs — can use the proxy, selected by configuration, not by hand-edited host files.
  • Provider health in Bob reflects the proxy: per-account status, cooldowns, quota, usage, model availability.
  • Operators can act on the proxy from Bob: refresh, enable/disable an account, test the connection, read recent proxy logs.
  • Web and mobile expose every screen through a coherent navigation model; no dead ends, no tablet-only routes.
  • Alerts for the things that stop work: proxy unreachable, a provider with no ready accounts, a runner gone stale.

Non-goals

  • Replacing CLIProxyAPI's own control panel. Bob shows what an operator needs to keep runs flowing, not every config knob.
  • Adding new providers to the proxy (Kimi/xAI accounts exist; wiring them as Bob run providers is a follow-up).
  • Fixing the App Store listing (screenshots, privacy labels) — tracked separately in Preflight.
  • Rewriting the Effect RPC migration on this branch; this plan builds on it as-is.

Implementation notes

The Claude CLI honours ANTHROPIC_BASE_URL + ANTHROPIC_AUTH_TOKEN; Codex needs the explicit Responses provider in config.toml because OPENAI_BASE_URL alone does not switch the wire API. Writing that file into the per-run CODEX_HOME keeps the host's shared config untouched, which the ops doc explicitly warns about. The broker already creates an ephemeral credential home outside the workspace; the proxy config goes there.

The probe stays an estimate: the outcome latch (402 / 401 / 429 from real runs) remains authoritative. The change is only what the estimate looks at.

Open Questions

Proxy-only in production? After Phase 1 verifies both providers through the proxy, should runner hosts drop direct OAuth entirely? Recommended: yes — one place to sign in, one place to watch, and the failed host probe goes away.
Mobile primary navigation. Tab bar (recommended, standard iOS pattern, five primaries) versus keeping the menu sheet. The sheet stays either way behind "More".
Kimi and xAI as Bob run providers. The proxy already holds accounts. Exposing them as dispatchable providers is a small follow-up once the proxy auth mode exists; not in this plan's scope unless wanted.
