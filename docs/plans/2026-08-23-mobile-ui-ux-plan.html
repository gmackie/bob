00Overview

The mobile app already runs Bob (Planning/Tasks) and OODA (conversations) on iPad, but every document it shows — research findings, plan output, vault notes, agent replies — is dumped as plain text, artifacts live behind modals, and the phone is a shrunken tablet with no job of its own. This plan gives each device a clear job and builds the three things that make the tablet worth carrying: a real markdown viewer, a persistent artifact pane that hosts every document type, and steering actions (approve, reject, commit, quote-reply) where the documents are. The phone becomes a triage inbox.

📱 iPhone — remote monitoring

The one job: “is anything on fire, and what needs my decision?”

  • Inbox of approvals, proposals, blocked sessions, failures, finished research
  • Approve / deny inline; quick-reply sheet for awaiting-input sessions
  • Everything else is a push away, never the landing screen

iPad — in-depth work, away from the desk

The one job: read & review long documents, then steer.

  • Research reports, plan drafts, proposals, diffs — rendered, not dumped
  • 3-pane reading layout; artifact pane persists across conversations
  • Steering, not authoring: approve/reject, commit draft, quote-reply

01Goals & non-goals

Goals

  • One product, one visual system (Bob's amber / warm-gray), one OODA-first / Bob-first preference driving both devices
  • Markdown viewer everywhere a document appears
  • Artifact pane replaces all document modals on tablet
  • Phone triage inbox replaces the Notifications screen
  • Every phase verified on both simulators and the physical iPad

Non-goals

  • A markdown editor — authoring stays at the desk
  • Merging PRs from a tablet (review + comment only, Phase 2)
  • A second accent palette for OODA
  • Mermaid rendering (Phase 3, if ever)
  • Replacing on-device STT (tracked separately, Phase 3)

02Decisions (from the grilling session)

Every branch of the design tree was visited; nothing below is assumed.

  • Device roles. Phone = triage only. Tablet = reading/review primarily, steering secondarily; no heavy authoring.
  • Home. Two views, OODA-first and Bob-first, toggled in Settings. The preference sets the tablet's default mode and segmented-control order, and the phone's default tab and tab order.
  • Artifacts that matter (ranked): research reports, plan drafts, proposals. Diffs are second tier. Raw tool output is always collapsed/secondary.
  • Markdown viewer is read-only with select-a-passage → quote-reply; the reply is a normal user_turn in the current conversation (no new event type).
  • Tablet layout. Landscape toggles 3-pane ↔ 2-pane (artifact replaces the conversation in 2-pane); portrait is 2-pane with push/back. The artifact pane is a document stack that persists across conversation switches until closed.
  • Proposals, jobs, vault notes, diffs all open in the artifact pane — modals are removed on tablet.
  • Research report contract. Phase 1 renders today's free-text result as markdown. Phase 2 adds a structured report { markdown, sources[] } to AgentJobResultV1 and the runner populates it.
  • Phone. 3-tab bar (Inbox · OODA · Bob). Inbox items: tool approvals, pending proposals, blocked/awaiting-input sessions, failed runs, finished research. Inline approve/deny + quick-reply sheet. iOS notification actions for approve/deny. Completed work items are not triage.
  • Plan drafts. Phase 1 renders planning output as markdown; Phase 2 lets the tablet commit a draft (the server already tracks “drafts awaiting commit”).
  • Diffs. Phase 2: review + comment (quote-reply) only; merge stays on web.
  • Offline. Phase 1 live-only; Phase 2 caches last-known state with a “last updated” stamp.
  • Done means Maestro flows on iPad Pro 13" + iPad Air 11" simulators and a Release build verified on the physical iPad, per phase.

03Current state (facts, not opinions)

There is no markdown rendering anywhere in the app. No markdown dependency in apps/mobile-bob/package.json; vault notes (vault-browser.tsx:103), tablet artifacts (InspectorPanel.tsx:129, monospace), agent job findings (job-inspector.tsx:191) and messages (message-list.tsx) are all raw Text.
  • Timeline kinds (features/chat/ooda-timeline.ts): message · tool · citation · proposal · job · evidence · system. Non-message kinds render through one generic ActivityRow; the row is not tappable — only small text buttons are. Tool results are captured but never rendered.
  • Research has no screen: createResearchJob reuses the Job modal. Result shape is AgentJobResultV1 { response?, summary?, artifactRef? } (packages/ooda/src/contracts/v1/jobs.ts:39) — one free-text blob, no sources, artifactRef not resolvable in-app.
  • Tablet inspector (InspectorPanel.tsx) has Files (Code/Diff viewer) · Artifact (plain text) · Tasks · Details. PlanningPane concatenates every output_chunk into one string for “Artifact”.
  • Phone is a bare Stack, lands on /chat unconditionally (features/chat/navigation.ts), reuses tablet panes; /planning/sessions/[id] has no artifact viewer at all. A Notifications “Inbox” exists with run-transition rows and tRPC notification.list; push taps deep-link via use-push-notifications.ts.
  • Already shipped this month (foundation this plan builds on): root AuthGate, QR/typed-code pairing, OODA sidebar conversation list + shared OodaConversationProvider, in-flow compact top bar, responsive dashboards, shared EmptyState, collapsed raw-output messages.

Markdown library choice

Use react-native-markdown-display (markdown-it based, pure JS, RN 0.83 / new-arch safe, custom renderers per node) with a small custom rule set: fenced code → CodeViewer (already exists, reuse its highlighting), tables → horizontal-scroll container, images → expo-image with max-width, links → in-app WebBrowser sheet. Rejected: react-native-markdown-renderer (unmaintained), WebView-based rendering (breaks text selection/quote-reply and feels non-native).

08Risks & mitigations

RiskImpactMitigation
Text selection inside a markdown renderer on iOS (for quote-reply) is fiddly across nested Text nodesmediumImplement selection at the block level first (long-press a paragraph/list item → quote that block); character-level selection is a stretch goal.
Agent output is not always valid markdown (raw JSON dumps seen in real data)mediumKeep the existing raw-output heuristic: JSON-looking content renders in the raw-output body (monospace, collapsed), never through the markdown parser.
Phase 2 contract change touches the runner (another deploy surface)mediumField is optional; Phase 1 viewer works on the blob, so UI never blocks on the runner rollout.
Triage ranking gets noisy in busy workspaceslowHard cap per bucket + “show all” link; order is fixed (blocked/approval → proposal → failed → research done).
Shared checkout with the SDLC session; CI deploys web from masterlowMobile-only commits; rebase before push; no wrangler deploy from this checkout.

10Open questions

  • Quick-reply on the phone: plain text only, or voice too? (Default: text; voice once Phase 3 STT lands.)
  • Should the OODA conversation list on tablet get search/filter in Phase 1? (Default: no; pinned + recency is enough until the list grows.)
  • Which vault (personal vs research) opens by default from an artifact link? (Default: follow the link's thread.)
