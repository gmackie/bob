Overview

Verify OpenTelemetry across the production request path, repair missing instrumentation and configuration, and prove publishing by finding exact canary trace IDs in the destination store. An exporter initialization message or healthy collector alone does not satisfy acceptance.

Goals and non-goals

Reuse the existing OTLP collectors and SigNoz storage. Give each service a stable identity, retain W3C parent correlation, flush on shutdown, bound export work and surface failures. Do not export credentials, request bodies, prompts or query parameters. Preserve application authorization, streaming responses and existing feature activation settings. Browser/mobile tracing and provider task generation are outside this production-server verification.

Risks and mitigations

OTLP HTTP success can contain partial rejection. Check the response body, and distinguish accepted export from stored telemetry. Keep bounded diagnostics independent of application success.

Node and Worker runtimes require separate initialization. Shared browser-safe code must not import the Node SDK. Keep exporters opt-in for host services; configure the deployed process explicitly. Use safe operation names instead of raw paths containing identifiers or bearer tokens.

Verification

Local receiver tests verify real serialized OTLP. Production acceptance records request status, trace ID, service identity, parent span, timestamp and collector/storage evidence. Host-derived metrics are verified separately from application traces. No authenticated visual or physical-device claim is implied.

Runtime architecture

Workers emit bounded OTLP HTTP exports through the existing public collector ingress. Host Node SDKs and the research Python SDK send to local OTLP receivers; collectors forward to SigNoz. Span-derived counters and latency distributions are generated in collectors. Journal log collection is a separate pipeline. Sentry retains error reporting while the shared Node SDK owns tracing.

Coverage limits and operational follow-up

  • Verified server request traces and derived request metrics. This release does not establish browser/mobile tracing, provider job execution, automatic cross-service outbound propagation or full WebSocket message/stream-duration tracing.
  • Journal logs are proven for the host and gateway. The current host collector allowlist excludes runner and research units; their logs are not claimed as published. Worker log export is not part of this trace exporter.
  • Research reports package version 0.1.0; the exact deployed source is recorded by its versioned runtime and release receipt. Node services report the release SHA as service.version.
  • The standalone execution daemon and obsolete Next.js unit were already crash-looping and were not included in this four-service cutover. Their runtime health and telemetry remain separate remediation work.
  • An independent SigNoz replacement briefly interrupted ingress during verification. Final canaries and metric samples were verified against the replacement storage after ingress recovered.

Rollback configurations and previous runtime artifacts remain preserved. Production verification establishes the named services and sampled requests at the recorded time, not continuous delivery during future collector outages.
