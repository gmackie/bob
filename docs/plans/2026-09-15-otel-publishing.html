Goals and non-goals

Reuse the existing OTLP collectors and SigNoz storage. Give each service a stable identity, retain W3C parent correlation, flush on shutdown, bound export work and surface failures. Do not export credentials, request bodies, prompts or query parameters. Preserve application authorization, streaming responses and existing feature activation settings. Browser/mobile tracing and provider task generation are outside this production-server verification.

Risks and mitigations

OTLP HTTP success can contain partial rejection. Check the response body, and distinguish accepted export from stored telemetry. Keep bounded diagnostics independent of application success.

Node and Worker runtimes require separate initialization. Shared browser-safe code must not import the Node SDK. Keep exporters opt-in for host services; configure the deployed process explicitly. Use safe operation names instead of raw paths containing identifiers or bearer tokens.

Verification

Local receiver tests verify real serialized OTLP. Production acceptance records request status, trace ID, service identity, parent span, timestamp and collector/storage evidence. Host-derived metrics are verified separately from application traces. No authenticated visual or physical-device claim is implied.
