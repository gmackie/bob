Overview

Bob's loop now runs unattended — Kanbanger card → agent → PR → review → repair → merge → deploy → card Done — but the only ways to watch it are a once-a-day digest, Sentry on failure, per-object pages, and psql. This plan adds /cockpit: a single screen that shows the whole loop moving. Two modes on one surface: wall (ambient, glanceable at 3 m, auto-focus) and ops (dense, interactive, full control). Everything animated is information: a card slides because it changed lanes, a tile pulses because an agent is streaming, a pipeline stage lights because CI moved.

Regions

Header strip — "is the loop alive?" Loop pulse (age of last cron tick; amber >7 min, red >15), pacing gauge (21/40 · earned 28 · burst 4), agent health chips (✓/✗ counts last 2h, dim = pulled by health gate), tracker sync age, open alerts. This row alone answers every question I spent this week in psql for.
Queue lanes — "what's next?" Five lanes (urgent → low) of dispatchable cards; ready pinned first. Card shows identifier, title, repo, agent override badge, age. Motion: a card slides lanes when priority changes; fades out when claimed (it reappears as an agent tile); a new card drops in from the top. Backlog is a count, not a lane — it's the human gate, not Bob's.
Agent stage — the hero. One tile per live session (execute / review / repair, colour-coded). Tile = agent icon + identity, task title + repo/branch, elapsed, live output tail (last ~6 lines, monospace, streaming), current tool call, file heat (touched paths, hottest first) and +123 −45 · 7 files. Wall mode auto-focuses: the tile with the most recent activity grows to 2× for ~20 s, then rotates. Ops mode: click to pin, expand to full transcript.

PR pipeline — "where is each change stuck?" One row per open Bob PR: code → CI → review → repair → merge → deploy. Stages: done ✓ / active (pulsing) / failed ✗ / waiting. CI stage expands to its Actions jobs (queued/running/pass/fail). Review stage shows the bob-reviewer verdict at this head. Repair shows attempt n/3. Parked PRs (repair cap hit, CI red with no repair left) sink to a "needs a human" group with the reason. Merge → 🚀 deploy evidence from the deploy tracker.
24h timeline. Horizontal strip: dispatches ·, PRs ▲, merges ◆, deploys 🚀, failures ✗ by agent colour; sparklines for dispatches/merges/errors; digest numbers inline (median claim→merge, merge rate).

bob-check — structured test/build progress V2

Today an agent running tests produces prose in a transcript; the UI can only show a spinner. bob-check is a runner-side wrapper (same for claude/codex/grok/cursor — the agent can't forget the format): it auto-detects the repo's commands (typecheck/lint/test/build from package.json, turbo, or .bob/check.yaml), runs them, and emits NDJSON that the runner forwards as check session events:

{"phase":"test","status":"running","started":"…"}
{"phase":"test","status":"progress","passed":41,"failed":1,"total":58,"current":"streak.test.ts"}
{"phase":"test","status":"failed","passed":57,"failed":1,"failures":[{"name":"computeStreak › gaps","file":"src/lib/streak.test.ts:42","message":"expected 3, got 4"}],"durationMs":8120}

A SKILL.md shipped into each worktree tells agents when to run it: after each meaningful change and before opening the PR. The tile shows a per-phase bar (typecheck ✓ · lint ✓ · test 57/58 ✗ · build –) instead of a spinner, and the PR pipeline's "code" stage can show the last local check result before CI even starts.

Incorporation: the mobile plan shares these contracts

The Bob + OODA iPad/iPhone plan gives the phone one job ("is anything on fire, what needs my decision?") and the tablet another (read & steer). Those are the cockpit's questions at different screen sizes — so they share plumbing, not just philosophy:

ContractCockpit useMobile use
cockpit.status (tRPC)Wall/ops full payload, 10 s pollPhone Inbox header ("on fire?" = alerts + prs.parked + blocked counts) and tablet queue/pipeline views — same types from services/cockpit/types.ts, no parallel endpoint.
cockpit mutations (V2, owner-only, audited)Ops-mode buttonsPhone inline approve/deny/retry/stop and tablet steering call the same procedures; iOS notification actions hit them too.
Gateway session events (output_chunk, tool_call, state, file_changes, V2 check)Agent tiles, file heat, per-phase check barsTablet session view + artifact pane get live diff stats and check bars from the identical events (mobile already speaks this WS for chat).
Pipeline derivation (services/cockpit/pipeline.ts)PR pipeline stripTablet PR review screen shows the same code→CI→review→repair→merge→deploy stages; one tested source of truth for "where is this change stuck".
Rule for both plans: if mobile needs loop data the cockpit payload lacks, extend cockpit.status — never add a sibling endpoint. The phone Inbox's approval/proposal items stay on their existing OODA/notification feeds; the cockpit contributes the SDLC health slice.

Risks & Mitigations

RiskLevelMitigation
Forgejo per-PR status/reviews/actions fan-out on every poll (27 open PRs × 3 calls)MediumServer-side 30 s cache keyed by head SHA; only refetch PRs whose head changed or whose CI was pending.
fs.watch recursive on macOS/Linux worktrees with node_modulesMediumIgnore node_modules, .git, build dirs; batch; cap paths per event; fall back to git status polling if watcher errors.
Wall browser memory growth from unbounded streamsMediumRing buffers per tile (last 200 lines), unsubscribe on tile unmount, periodic page reload in wall mode (every 6 h).
Controls fire on production by mistakeMediumOwner-only, confirm on destructive (stop/reject/cap), audited, and read-only V1 ships first.
Animation reads as noiseLowV1 = state-change motion only; every animation maps to an event; levels are opt-in.

Verification (V1 done means)

  1. Open /cockpit on a wall: within 10 s it shows the real queue by lane, every live session as a tile with streaming output, every open PR's pipeline state, the 24h strip.
  2. Promote a card to Urgent in Kanbanger → it slides lanes within one sync.
  3. Auto-drain claims it → card fades, tile appears, output streams <1 s behind the agent, file heat and +/- update within 3 s of edits.
  4. PR opens → pipeline row appears; CI job states change live; bob-reviewer verdict lights the review stage; merge → deploy 🚀.
  5. Kill the gateway → stale banner → reconnects without reload.

Open Questions — resolved (08-23)

  • Wall device: assume Linux (Chromium kiosk); fullscreen via ?kiosk=1, no Safari-specific work.
  • OODA sessions: the cockpit shows both Bob and OODA sessions; OODA is hidden by default behind a toggle (same gateway, different sessionType/thread origin).
  • Sound: on by default, with a settings toggle (and auto-muted under prefers-reduced-motion).
