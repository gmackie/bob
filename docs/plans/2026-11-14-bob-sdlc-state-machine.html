Bob SDLC state machine: drill-down, monitoring, orchestration Design · rev 2

2026-11-14 · gmackie/bob @ master 4fe38915 · BOB-75 · Claude with Graham · companion: t3code thread “Explore Unified Orchestration TUI”

Decision: the durable factory coordinator (packages/bob/coordination) is the SDLC state machine and the orchestration API. This work adds what it lacks: a public live edge (a Durable Object fed by an outbound exporter) and four surfaces on top of it: web, mobile, an Ink TUI and the t3code plugin. The coordinator remains the only writer.
Revision note: rev 1 was explored on a stale seed (3b40bf09). It proposed a new spec, a single-writer DO and a t3 bridge, all of which BOB-41…68 already ship in the coordinator and ooda-runner. Rev 2 builds on those instead of duplicating them.

Goals and non-goals

Goals
  • Draw the coordinator's machine on web, mobile, TUI and plugin, all from one presentation spec
  • Drill down Fleet → Project → Repo → Item → Attempt, plus a Plan DAG view
  • Orchestrate through the coordinator's own operations, with tiered confirmation
  • Live updates everywhere with one Bob login
Non-goals
  • A second state machine or a second writer
  • Drawing the legacy auto-drain loop (it migrates onto plans separately)
  • Changing contract.forge semantics. Additions only: an export stream and per-user principals
  • Replacing /cockpit

1 · The machine: coordinator ItemState

Each item is a Kanbanger issue with an execution target, inside a plan. The states come straight from contract.forge; the green tags are the milestones that downstream dependencies wait for. A presentation spec adds only layout, labels, owners and the attention mapping, and it's generated from the enums so the two can't drift apart.

2 · Drill-down

L1Fleet

Item counts per state, active plans, every attention item

L2Project

A BizPulse startup and the ForgeGraph apps it owns; anything else goes under “Unassigned”

L3Repo

From ExecutionTarget / RepositoryRef

L4Item

Path through the machine, milestones, operations, evidence, its issue

L5Attempt

ThreadRef → live t3 tail, pending input, CI phases

Plan view is a second way into the same data: one plan's dependency DAG, with each edge labelled by the milestone it waits on (Dependency.requiredMilestone) and each node coloured by its item's state. It's reachable from L1 and from any item.

3 · Architecture: the coordinator is the truth, the edge is public

Edge exporter (coordinator, new)

Opens a websocket out to the DO. It sends the CoordinationChange pages with the changed plan and item snapshots, resumes from a checkpoint, and receives commands on the same socket. Commands go through the coordinator's existing handlers with Idempotency-Key = commandId.

SdlcEdge DO (Bob Worker, new)

Caches the snapshot, keeps a replay buffer, and fans out to clients over hibernatable websockets. It maps a Bob user to a coordinator principal, enforces command tiers and confirmations, and never decides state. If the coordinator is offline, it serves the last snapshot read-only with a banner.

Tail relay (new)

Runs next to the coordinator. It uses the t3 client to follow the threads of running attempts (ExecutionAdmission.thread) and forwards short tail frames and pending input to the DO. Frames are ephemeral and never stored.

4 · Orchestration: the coordinator's operations, tiered

Tier 1 no confirm

ResolveInput (answer an agent) · ReconcileItem · pause or resume via ControlPlan

Tier 2 confirm

RetryItem · CancelItem · ControlPlan start/cancel · TriggerPlan · Create/UpdatePlan · RequestRelease open-pr/approve/merge · RequestValidation · RequestDeployment deploy

Tier 3 typed confirm

RequestDeployment promote/rollback. You type the repo name to confirm.

Every command carries the item or plan's resourceVersion; the coordinator rejects stale ones after replaying its idempotency check. Agents propose tier 2 and 3 actions through MCP, and a human confirms them in a view. The coordinator's principal policy still applies on top of the tiers.

5 · Surfaces

The shared @bob/sdlc-view package holds the presentation spec generated from contract.forge (layout, labels, owners, attention, tiers), level navigation, the delta reducer and which commands are allowed. Surfaces only draw.

Web /sdlc

  • State graph with counts and attention badges; edges animate on transitions
  • Plan DAG view; breadcrumb drill-down; evidence and actions side panel
  • Attempt level: live tail, pending input, CI phases

Mobile (Expo)

  • Graph at L1–L3 with react-native-svg; list-first at L4–L5
  • Attention tab with push on new waiting-input, review gates and failures
  • Confirmation sheets for tiers 2 and 3

TUI apps/bob-tui

  • Ink 6 on Node; one Bob device login
  • Panes: tree · box-drawn machine or plan DAG · evidence; inbox strip
  • enter/esc drill · : palette · a answer · r retry · m merge · p promote (typed)

t3code plugin

  • bob_sdlc MCP App view: shows the item behind the current thread (matched by ThreadRef), or Fleet for a project
  • Reads from the edge; agent tools keep using the coordinator's MCP

Failure handling

FailureBehaviour
Coordinator or exporter offlineThe edge serves its last snapshot read-only with “coordinator offline since …”; commands are refused with a reason.
Exporter reconnectsIt resumes from its checkpoint. If the cursor has expired, it sends a fresh snapshot, as the contract requires.
Command outcome unknown (socket dropped mid-command)The client retries with the same commandId; the coordinator replays the stored receipt.
execution-unknownShown as stalled, with ReconcileItem offered. Never shown as failed.
Tail relay or ForgeGraph detail missingThat panel shows “live detail unavailable”; state and actions are unaffected.
