Overview

The goal: every Todo issue in Kanbanger (tasks.gmac.io, the Linear-compatible tracker) is picked up by Bob without a human in the loop, coded by an agent, pushed as a PR, reviewed, repaired if needed, merged, deployed, and closed back in Kanbanger. Backlog stays the human gate: promoting a card to Todo is the only thing a person has to do.

Most of this pipeline already exists and is switched on in production (auto-drain, bob-reviewer, auto-repair, auto-merge, checklist driver). This plan is therefore mostly about closing the gaps that make the existing loop stall, not greenfield. Live production numbers at time of writing:

Goals

  • Kanbanger is the single queue. Todo = auto-executable; Backlog = human gate.
  • Every state change is mirrored back to Kanbanger (started / in review / done / blocked) with PR links.
  • The loop never stalls silently: stale sync, dead auth, reaper spikes, and zero-throughput all alert.
  • Merge → deploy → done is driven by the cron, not by an open browser tab.
  • One executor. Retire task-runner.js's execution role.

Non-goals

  • Migrating Kanbanger to D1 (separate repo, in beta already).
  • Rewriting auto-drain's agent choice (agent-router scoring) — later.
  • Checklist/plan-driven execution (P2/P3 of the 2026-08-14 plan) — orthogonal, left alone.
  • tRPC → Effect-RPC migration.

Phases

  • P0 — Unblock intake (today): Kanbanger API up, sync reconciles status both ways, stale-sync alert.
  • P1 — Close the loop (1–2 days): merge→done, Kanbanger write-back, reaper rollback, one-off backfill of the 372+29 stranded items.
  • P2 — Ship stage (2–3 days): cron-driven pipeline advance, ForgeGraph deploy after merge, retire task-runner execution.
  • P3 — Harden & observe (ongoing): throughput metrics, budget/backpressure, daily digest, agent routing.

Decisions (made to keep moving — shout if wrong)

  • Kanbanger owns the queue; Bob mirrors. Bob's Board becomes a view, not a second source of truth. Human gating happens in Kanbanger (Backlog→Todo).
  • Bob's backlog remains excluded from auto-drain. It maps 1:1 to Kanbanger Backlog, so the gate is preserved.
  • done means merged for projects without a ForgeGraph deploy binding, and deployed-healthy for those with one (P2).
  • Retire task-runner.js rather than teach it to share a lock. Two executors is the bug.
  • Status write-back uses the existing planningWriteService rather than a new client.
